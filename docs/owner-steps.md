# Що зробити власниці проєкту

Тут зібрано кроки, які може зробити лише людина: доступи до GitHub, рішення та перевірки. Решту (сервер, код, перевірки) робить Claude Code.

## Зараз, по черзі

### 1. Репозиторій для шлюзу (5 хвилин)

Шлюз Claude Code тепер окремий проєкт. Локально він уже лежить у `~/Desktop/projects/claude-gateway` з усією історією, бракує лише репозиторію на GitHub.

1. Відкрийте https://github.com/new.
2. Owner: `FixerHack`, назва: `claude-gateway`.
3. **Public.** Секретів у коді немає, а сервер клонує його без пароля. Якщо хочете Private, скажіть Claude: тоді знадобиться ще один deploy key на читання.
4. **Не** ставте галочок README, .gitignore чи license (вони вже є локально) і натисніть Create repository.
5. У терміналі на Mac:

```bash
cd ~/Desktop/projects/claude-gateway && git push -u origin main
```

Після цього скажіть Claude, що репозиторій створено. Він запушить war-predictor і перенесе шлюз на сервері на новий репозиторій. `.env` і токени при цьому зберігаються, простій триває кілька секунд.

### 2. Ключ для автопублікації карти (3 хвилини)

Сервер публікує карту кожні 30 хвилин, але для цього йому потрібен дозвіл на запис у GitHub. Claude створить ключ на сервері й надішле вам **публічну** частину. Вона починається з `ssh-ed25519`, і показувати її безпечно.

1. GitHub → `FixerHack/war-predictor` → **Settings** → **Deploy keys** → **Add deploy key**.
2. Title: `server-pages`. Key: вставте надісланий рядок.
3. **Поставте галочку Allow write access** і натисніть Add key.
4. Скажіть Claude «ключ додано».

Без цього кроку все інше працює, просто карта на сайті не оновлюється.

### 3. Перевірка бота (2 хвилини)

У Telegram відкрийте `@warpredbot` і надішліть `/start`. Перевірте:
- **панель:** Польща має показувати низький рівень (раніше хибно було 5.4);
- **рядок «Оновлено»:** у ньому тепер є «перевірка кожні … год»;
- **кнопка 🔄 Оновити:** працює миттєво.

## Коли буде час (необов'язково, але корисно)

### 4. Захист гілки `main`

GitHub → Settings → **Rules** → **Rulesets** → New branch ruleset:
- **Target branches:** Include default branch.
- **Rules:** увімкнути **Restrict deletions** і **Block force pushes**.
- **Require a pull request** не вмикайте: Claude зливає перевірені гілки в `main` локально й пушить, і з цим правилом пуш не пройде.
- **Bypass list** лишіть порожнім.

Тоді deploy key сервера не зможе переписати `main`: він пушить лише в `gh-pages`.

Ще в тому самому місці (Branches) видаліть стару гілку `claude/funny-planck-leoxip`.

### 5. Сигнал «сервер живий» (healthchecks.io, безкоштовно)

1. Зареєструйтеся на https://healthchecks.io і натисніть Add Check.
2. Задайте Period **15 minutes** і Grace **30 minutes**.
3. Скопіюйте Ping URL (`https://hc-ping.com/...`) і надішліть Claude. Він впише його на сервері як `HEALTH_PING_URL`.

Якщо сервер чи healthcheck перестануть працювати, вам прийде лист.

### 6. GitHub Actions — можна не розблоковувати

Actions заблоковані через білінг, але проєкту вони не потрібні:
- перевірки (`make check`) Claude запускає перед кожним злиттям;
- карту публікує сервер.

Якщо колись розблокуєте, CI (`.github/workflows/ci.yml`) просто запрацює сам.

### 7. Рішення, які потребують людини

- **Перелік джерел:** затвердити [docs/sources.md](sources.md) (S1.4).
- **Юридичне застереження:** текст для бота й сайту, тобто «не прогноз, не порада» розгорнуто (S1.7, S11.4).
- **Ручна перевірка 50 класифікацій** (S6.3). Claude підготує таблицю (заголовок або зміна, мітка, ваша оцінка), а ви позначите хибні. Хибні тривоги з Польщею і литовськими навчаннями показали, що така перевірка справді потрібна.
- **Токен UCDP** (S10.3), необов'язково: потрібен як друге автоматичне джерело статусу війни.
